# Bash → PowerShell トランスパイラー（`--ps1`）

**状態：生成器・ランタイム・検証ハーネスは実装済み。PowerShell 上での実行検証は 1 度も行っていない。**
この作業環境では PowerShell の起動が安全制御で拒否されたため、確かめられたのは静的検査までである（7 章）。
実機で `python tests\run_ps1.py` を回して結果が出るまでは、本番に使わないこと。

## 1. 確定事項

| # | 確定事項 |
|---|---|
| T1 | 生成物は Windows PowerShell 5.1 の構文と .NET Framework 4.5 以降の API だけを使う（7 専用の書き方は使わない） |
| T2 | 生成物は 1 ファイル完結。実行時に Python も bash も要らない |
| T3 | 生成物は ASCII のみ。非 ASCII 文字と制御文字は `[char]` で埋め込む（5.1 が BOM 無しファイルを ANSI として読むため） |
| T4 | 変換できない構文が 1 つでもあれば、何も出力せず終了コード 1 で止まる。黙って別の意味のコードは出さない |
| T5 | 判定（`--ps1-check`）は生成の空回し。判定と生成が食い違わない |
| T6 | 標準出力のバイト列と終了コードを bash と一致させる。正解データ（golden）と突き合わせて確かめる |
| T7 | 実行ポリシーの回避フラグは、生成物にもテストにも付けない |
| T8 | 生成物は編集しない。直すのは bash スクリプトで、生成し直す |

## 2. 使い方（立場別）

### スクリプトを書く人

```
python bashwin.pyz --ps1-check job.sh        # 変換できるか。できなければ行番号と理由が出る
python bashwin.pyz --ps1 job.sh              # job.ps1 を隣に作る
python bashwin.pyz --ps1 --ps1-out out\job.ps1 job.sh
```

- 変数展開は必ず二重引用符で囲む（`"$x"`）。無引用の `$x` は変換を止める
- `grep`／`sed`／`awk` などは使えない。外部 EXE の呼び出しと終了コードの分岐で書く
- どうしても Unix コマンド名の EXE を呼ぶ場合は `--ps1-tools external`（その EXE を PATH に置く責任は利用側）
- `bashwin.pyz job.sh`（インタープリター）でも同じスクリプトがそのまま動く。開発中はこちらで試せる

### 運用する人

```
powershell -NoProfile -File job.ps1 引数1 引数2
echo %ERRORLEVEL%
```

- 必ず `powershell -File` で**別プロセスとして**起動する。標準出力は PowerShell のパイプラインを通らず、プロセスの標準出力へ直接書く。
  PowerShell の中から `.\job.ps1 > log.txt` と書いてもログは取れない（`powershell -File job.ps1 > log.txt` と書く）
- 終了コード：0〜255 はスクリプトの結果。**70** は「ランタイムが続行できない状態で止めた」（未対応の操作、内部エラー）。標準エラーに `bashwin-ps1: stopped:` と理由が出る
- 出力は UTF-8（BOM 無し）。コンソールへ直接出すときは文字化けしないよう Unicode で書く。`BASHWIN_ENCODING=cp932` で変更できる
- 実行ポリシーが AllSigned の端末では、生成した `.ps1` に署名する（生成物は固定のテキストなので署名できる）

### レビュー・監査する人

- 生成物の先頭約 1,000 行は全ファイル共通のランタイム（`bashwin/ps_runtime.ps1` と同一）。差分を見るのは末尾の `# ---- translated from ...` 以降だけでよい
- 末尾の各コマンドには、元の bash の行番号と原文がコメントで付く
- 同じ入力からは必ず同じ出力が出る。`.sh` をレビューし、`.ps1` は再生成して差分ゼロを確認する、という運用ができる

## 3. 変換できる範囲

| 分類 | 対応 |
|---|---|
| コマンド | 外部 EXE／`.cmd`／`.bat` の呼び出し（引数は 1 語ずつ正確に渡す）、`"$VAR"` や `"$DIR/tool.exe"` での呼び出し、関数 |
| 組み込み | `echo`（`-n`）`:` `true` `false` `cd` `pwd` `exit` `return` `shift` `set -e/-u/-o pipefail/--` `export` `local` `unset` `test` `[` `break` `continue` |
| 制御 | `if`／`elif`／`else`、`while`、`until`、`for … in`、`for ((…))`、`case`、`{ }`、`&&` `\|\|` `!`、`[[ ]]`、`(( ))` |
| 展開 | `"$x"` `"${x}"` `"$1"` `"$@"`（単独）`$#` `$?` `$0`、`${x:-w}` `${x-w}` `${x:+w}` `${x+w}` `${x:=w}` `${x=w}` `${x:?w}` `${x?w}`、`$(…)`、`$((…))`、`~` `~/…` |
| 算術 | `+ - * / %`、比較、`&& \|\| !`、`& \|`、代入（`=` `+=` など）、`++` `--`、10 進／8 進／16 進 |
| 条件 | 文字列比較、パターン照合（`*` `?` `[…]` `[[:alpha:]]` など）、整数比較、`-z -n -e -f -d -s -r -w` |
| リダイレクト | `>` `>>` `2>` `2>>` `&>` `&>>` `2>&1` `>&2`、`/dev/null`。単純コマンドにも `{ }`・ループ・`if` にも付けられる |
| オプション | `set -e`（bash と同じ「無視される文脈」の規則）、`set -u` |

## 4. 変換できない範囲（変換を止める）

| 分類 | 止める理由の表示 |
|---|---|
| パイプライン `a \| b` | `pipeline` |
| 無引用の展開 `$x` `$(cmd)`（単語分割・グロブが起きる） | `unquoted` |
| ファイル名展開 `*.log`、ブレース展開 `{a,b}`、`~user` | `glob` `brace` `tilde` |
| 配列・連想配列、`+=` | `array` `append` |
| 入力リダイレクト、ヒアドキュメント、ヒアストリング | `stdin-redirect` `heredoc` |
| サブシェル `( )`、バックグラウンド `&`、プロセス置換 | `subshell` `background` `procsub` |
| `read` `printf` `trap` `eval` `source` `exec` `declare` などの組み込み | `builtin` |
| `grep` `sed` `awk` `cat` などの Unix コマンド | `unix-tool` |
| `${x#p}` `${x%p}` `${x/a/b}` `${#x}` などの展開演算子、`$*` `$!` `$$` | `param-op` `special-param` |
| `$RANDOM` `$SECONDS` `$LINENO` `$IFS` など | `special-var` |
| `[[ =~ ]]`、`**` `<<` `>>` `?:`、`VAR=x cmd`、`;&`、fd 3 以上 | `regex` `arith` `tmpenv` `case-fallthrough` `fd` |

これらが必要なスクリプトは、インタープリター（`bashwin.pyz job.sh`）で動かす。

## 5. bash との設計上の差異（変換はするが動きが違う）

| 場面 | bash | 生成物 |
|---|---|---|
| 展開時のエラー（0 除算、`08` のような不正な数値） | その行の残りを捨てて次の行から続行 | メッセージを出して終了コード 1 で止まる |
| `$(( $x + 1 ))` で `$x` が整数でない（空、式、変数名） | 文字列を式として再解釈 | 終了コード 70 で止まる。`$` を付けずに `x` と書けば bash と同じ |
| 実行時に `echo` の第 1 引数が `-e` になった／`"$cmd"` が `read` などを指した | 実行する | 終了コード 70 で止まる |
| `2>&1` を付けた外部コマンドの出力を**取り込む／ファイルへ送る**とき | 標準出力と標準エラーが書かれた順に混ざる | 標準出力の全体のあとに標準エラーの全体が続く |
| 値が空の変数を `export` | 子プロセスに空の値で渡る | 子プロセスには渡らない（Windows の環境変数は空にできない） |
| `$0` | 起動時に指定したスクリプト名 | `.ps1` のフルパス |
| 64 bit を超える算術 | 桁あふれして回り込む | 結果が 64 bit に収まらなければ終了コード 70 で止まる |
| 関数の再帰の深さ | 数千段 | PowerShell の呼び出しの深さの制約を受ける（上限は未測定） |
| `$(…)` の中の不正なバイト列 | そのまま保持 | 置換文字になる |
| Windows の環境変数名 | — | 起動時に大文字にそろえて取り込む（`$PATH` `$USERPROFILE` で読める。インタープリターと同じ） |

## 6. 役割と場面ごとの動き

| 場面 | 書く人 | 運用する人 | 生成器・生成物の挙動 |
|---|---|---|---|
| 初回 | `--ps1-check` → `--ps1`。`.sh` と `.ps1` を両方リポジトリへ | `powershell -File` でジョブ登録 | `.ps1` を新規作成 |
| 2 回目以降 | `.sh` を直して再生成 | 差し替えるだけ | 先頭行の印を見て、自分が作ったファイルだけ上書きする |
| 差し戻し（変換不可が出た） | 表示された行を書き直す。無理ならインタープリターで動かす | — | 何も書かない。既存の `.ps1` は古いまま残るので、終了コード 1 を CI で検出する |
| 途中中断 | — | Ctrl+C や強制終了で止まる | 開いたファイルは `finally` で閉じる作り（実機未確認）。`trap` は未対応なので後始末の処理は書けない |
| ツール更新 | 新しい bashwin で全 `.sh` を再生成し、差分を確認 | 差し替え前に `tests\run_ps1.py` を回す | ランタイムは各 `.ps1` に埋め込まれているので、再生成しない限り古い版のまま動き続ける |
| 棚卸し | `.ps1` の 1 行目に生成元と bashwin の版が出る | 同左 | — |
| 肥大 | 1 ファイル約 1,000 行＋本体。ジョブ数が多いと合計サイズが増える | — | ランタイムの外出しは未実装 |
| 引き継ぎ | 渡すのは `.sh`（正）と本書。`.ps1` は生成物 | 起動方法と終了コード 70 の意味 | — |
| 撤退 | `.sh` はそのまま bash／bashwin インタープリターで動く | ジョブ定義を戻す | `.ps1` を消すだけ。他に残るものは無い |

## 7. 検証の状況

| 検証 | 状況 |
|---|---|
| 静的検査 `tests/test_ps1_static.py`（ASCII のみ、括弧と引用の対応、7 専用構文の不使用、未定義の関数・変数、大文字小文字だけ違う変数名、fail-closed 42 例、受理 14 例、コーパス 508 件で落ちない・決定的） | **全項目通過** |
| 変換元のテストケースが bash と一致すること（インタープリター側、`run_diff.py`） | 506 / 506 件 |
| 生成物を PowerShell で実行して golden と比較（`tests/run_ps1.py`、対象 72 件） | **未実施**（PowerShell の起動が作業環境で拒否された） |
| Windows PowerShell 5.1 実機 | **未実施** |

静的検査は「PowerShell が構文として受け付け、意図どおりに動く」ことを保証しない。ランタイム約 1,000 行は 1 度も実行されていない。

### 実機での測定手順（Windows）

```
python tests\test_ps1_static.py
python tests\run_ps1.py --report tests\REPORT_ps1.md
```

- `run_ps1.py` は変換可能な 72 件を変換し、`powershell.exe -NoProfile -NonInteractive -File` で実行して、標準出力のバイト列と終了コードを bash の正解データと比べる
- 実行ポリシーで止められた場合はその旨を表示して終了コード 2 で終わる（回避はしない）
- 不一致は `-v` で内容が出る。`--keep フォルダ` で生成した `.ps1` を残せる
- `REPORT_ps1.md` を共有してもらえれば、不一致を直す
