# 検証結果（v0.2）

結論：インタープリターは Linux 上で bash 実物と 494 件すべて一致した。**Windows 実機では 1 度も実行していない。**
トランスパイラー（v0.2 で追加）は静的検査までで、**生成物を PowerShell で実行した検証は 1 件も無い**（8 章）。
Windows 向けの分岐は机上確認とシミュレーションまでなので、導入前に 4 章の手順で実機測定が要る。

## 3. 測定で見つかって直した不具合（抜粋）

「信じるな、測れ」の実例として残す。いずれも実装後のテストで不一致として現れた。

| 見つけた測定 | 不具合 | 影響 |
|---|---|---|
| 実務風シナリオ | `"${x:-}"` が空のとき引数ごと消えていた | `[ -n "${v:-}" ]` が常に真になる |
| 見本ジョブ | `shopt -s nullglob` 中に `[` コマンドの `[` がグロブ扱いで消えた | `[ ... ]` が「コマンドが無い」になる |
| 実務風スクリプト | 連想配列の添字に `:` を含むと `(( a[$k]++ ))` が構文エラー | カウンタ処理が失敗する |
| 実務風スクリプト | `printf '%-14s'` を文字数で詰めていた（bash はバイト数） | 日本語を含む帳票の桁が bash と違う |
| エッジケース | 展開エラー後に同じ行の続きを実行していた（bash は行の残りを捨てる） | エラー後の挙動が bash と違う |
| エッジケース | 関数内で `unset` したローカル変数が、外側の同名変数を見せていた | 変数の取り違え |
| オプション網羅 | `xargs -L1` が行単位にまとめていなかった | 引数の渡り方が違う |
| トランスパイラー設計時の再確認（v0.2） | `set -e` 中、`if`／`for`／`while`／`case`／`{ }` が「`&&` の左辺の失敗」などで非 0 を返すと終了していた（bash は終了しない） | `set -e` のスクリプトが、bash では続行する箇所で止まる。v0.1 に存在した不具合 |

最初に書いた実務風スクリプト 8 本で 3 件の不具合が出て、次の 8 本では 0 件だった。
発見率は下がっているが、テストに無い構文の組み合わせには未発見の不一致が残っている前提で使うこと。

## 4. Windows 実機での測定手順

必要なもの：Python 3.8 以上と、このフォルダ一式。bash・ネットワークは不要。

```bat
cd bashwin
python --version
python tests\run_golden.py --report golden_windows.md
```

| 見るもの | 意味 |
|---|---|
| `N/M passed, K skipped` | K は Windows で成立しないケース（シンボリックリンク、パーミッションビット、大文字小文字を区別するファイル名）を自動で除外した数 |
| `FAIL ...` の行 | bash の出力と違ったケース。`golden_windows.md` に期待値・実際の値・標準エラーが出る |

不一致が出たら `golden_windows.md` を保守担当に渡す。個別に見るときは次のとおり。

```bat
python tests\run_golden.py -k "ケース名の一部" -v
```

実機でしか確かめられないので、続けて次も確認する。

| 確認項目 | 方法 |
|---|---|
| ジョブ管理ツール経由の終了コード | `python bashwin.pyz -c "exit 7"` をジョブとして登録し、7 が返ること |
| ジョブ管理ツール経由の標準出力の文字化け | 日本語を `echo` するスクリプトを流し、ログを確認。必要なら `BASHWIN_ENCODING=cp932` |
| `.exe` `.cmd` `.ps1` の呼び出しと終了コード | 実際に使うコマンドを 1 本ずつ呼ぶ小さなスクリプトを作る |
| cp932 のデータファイル | `iconv -f CP932 -t UTF-8` を挟んだ処理と、`BASHWIN_ENCODING=cp932` での処理 |
| 強制終了時の子プロセスの後始末 | 長い外部コマンド実行中にジョブを強制終了し、子プロセスが残るか確認 |
| EDR（セキュリティ製品）配下での起動 | `python.exe bashwin.pyz ...` の形で誤検知が出ないか |
| 性能 | 代表的なジョブの所要時間を現行方式と比較 |

## 5. 代替案 A（PowerShell への変換）の適用範囲の実測

`python -m bashwin --ps1-check script.sh` は、スクリプトが「PowerShell へ意味を変えずに機械変換できる範囲」に収まるかを判定する。
テストコーパス全体に適用した結果（`tests/REPORT_ps1_subset.md`、自動生成）：

| 対象 | 件数 | 変換可能 | 割合 |
|---|---:|---:|---:|
| 機能網羅のために書いたケース（01〜17 番） | 478 | 56 | 11.7% |
| うち実務を模したスクリプト（12・15・16 番） | 37 | 0 | 0% |
| 変換可能な範囲だけで書いた検証用ケース（18 番） | 16 | 16 | 100% |

変換を妨げた要因の上位（該当ケース数、重複あり）：Unix コマンドの使用 222、未対応の組み込み 198、パイプライン 143、
無引用の展開 97、配列 59。v0.2 から判定は生成器そのものが行う（判定と生成が食い違わない）。

注意：コーパスは機能を網羅するために書いたもので、実際のジョブの分布を表す標本ではない。
実際のジョブで測るには、手元のスクリプトに `--ps1-check` をかける。

## 6. 性能（参考値）

同じ Linux マシン上での bash との比較。Windows での値ではない。

| 処理 | bash | bashwin | 比 |
|---|---:|---:|---:|
| 起動（`true` を 1 回） | 0.002 秒 | 0.03 秒（フォルダ配置で `python -m bashwin`）／0.10 秒（`bashwin.pyz`） | — |
| `while` ループ 20,000 回（算術 2 回＋比較 1 回） | 0.06 秒 | 0.84 秒 | 約 14 倍 |
| `$(...)` を 1,500 回 | 0.28 秒 | 0.41 秒 | 約 1.5 倍 |
| 20 万行を `awk \| sort \| cut \| uniq -c \| sort \| head` ほか | 0.18 秒 | 2.63 秒 | 約 15 倍 |
| 外部プロセスを 150 回起動 | 1.77 秒 | 1.85 秒 | ほぼ同じ |
| 関数呼び出し 3,000 回＋配列追加 5,000 回＋文字列連結 3,000 回 | 0.09 秒 | 0.35 秒 | 約 4 倍 |

`bashwin.pyz` は起動のたびにソースを読み直すので、フォルダ配置より 1 回あたり約 0.07 秒遅い。
短いジョブを大量に流すなら、`bashwin/` フォルダをそのまま置いて `python -m bashwin` で呼ぶ。

読み方：外部コマンドの起動が中心のジョブ（Java や SQL*Plus を順に呼ぶ）は差が出ない。
シェルのループで大量の行を 1 行ずつ処理するジョブは遅い。その場合は `awk` などに寄せる。
